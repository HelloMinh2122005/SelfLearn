#### Notes
- C5.11: Predefined CI variables `CI_REGISTRY_USER` and `CI_REGISTRY_PASSWORD` are documented in GitLab CI predefined variables. `CI_REGISTRY_PASSWORD` shares its value with `CI_JOB_TOKEN` and is valid only during job execution.
- C5.12: GitLab Container Registry authentication guidelines recommend `--password-stdin` over `-p` to prevent sensitive credentials from appearing in process tables.
- C5.13: Kubernetes documentation explicitly contrasts mutable tags that can be repointed against fixed digests, noting potential drift/rollback issues when tags are reused.
- C5.14: Container image digests (`@sha256:...`) provide content-addressable immutability, ensuring identical execution across environments.
- C5.15: GitLab predefined variables define `CI_COMMIT_SHORT_SHA` as the first 8 characters of commit SHA and `CI_COMMIT_TAG` as commit tag name available on tag pipelines.
- C5.16: `artifacts:reports:dotenv` in GitLab CI captures key-value pairs from `.env` files and exposes them as pipeline variables for dependent/downstream jobs.
- C5.17: GitLab CI layer caching documentation details inline caching via `--build-arg BUILDKIT_INLINE_CACHE=1` and `--cache-from` to pull cache sources from registries on ephemeral runners.
- C5.18: Buildah CLI documentation confirms `--digestfile` writes the resulting content digest to a specified file upon pushing.
